# 브랜드·규모·학교·역 접근성 후보 실험

2026-09-06. 운영 모델은 `estate-reference-v4`를 유지하며, 별도 모델 `estate-preferences-v5-research`를 학습했다. 최종 실험은 주소 표기를 정규화한 전체 자료 기준이다.

## 무엇을 시험했나

기존 v4의 면적·연식·지역·과거 가격 입력은 유지하고 아래 요소를 추가했다. 모든 구성은 같은 LightGBM 구조를 사용한다. 가산점을 사람이 정하지 않고 추가 입력이 기준가격 오차를 낮추는지 검증한다.

| 요소 | 구현 | 해석과 한계 |
|---|---|---|
| 브랜드 | 단지명에서 래미안·롯데캐슬·힐스테이트·아이파크·자이·푸르지오·더샵·e편한세상·동문 등을 정규화해 범주화 | 1군/2군의 임의 점수나 고정 프리미엄 없음. `현대`와 `힐스테이트/아이파크`, `삼성`과 `래미안`은 구분. 공동 브랜드와 미확인도 별도 범주 |
| 전체 세대수 | `log(1+세대수)` | 같은 단지의 여러 평형이 동일한 단지 값을 공유. 평형마다 반복된 전체 세대수를 합산하지 않음 |
| 신축 | 기존 `age = 대상 연도 − 준공연도` 유지 | LightGBM이 연식의 비선형 효과를 학습. 신축 가산점을 또 더하지 않음 |
| 평형 | 기존 전용면적·5평 구간·유사 면적 과거 가격 유지 | 정확한 전용면적을 보존. 같은 정수 평수라고 합치지 않음 |
| 초등학교 근접성 | 그해 1월 1일 전 설립된 학교까지의 직선거리 로그와 500m 이내 여부 | 통학구역, 초등학교를 품은 단지 경계, 보행 안전을 확인한 지표는 아님 |
| 운영 역 접근성 | 확인된 역사 집합까지의 직선거리 로그 | 연초까지 개통·운영이 확인된 역만 사용. 역사 중심 좌표이며 출입구까지 실제 도보시간은 아님 |

기존 과거 가격에는 이미 브랜드·입지·규모의 시장 평가가 간접 반영되어 있다. 별도 입력의 효과는 특히 전년도 동일 평형 거래가 없는 경우에 나타날 수 있다.

## 실제 비교 결과

총 98,410개 시험 평형을 그대로 유지했다. 추가 정보가 없는 평형도 제외하지 않고 결측값으로 처리했다. 2023년은 과거 검증에서 ML 혼합 비중이 0으로 선택되어 모든 구성의 결과가 동일하다.

| 구성 | 입력 수 | 2023 MAE | 2024 MAE | 2025 MAE | 2025 개선율 |
|---|---:|---:|---:|---:|---:|
| 기존 v4 | 17 | 502.31 | 330.98 | 385.02 | 기준 |
| 브랜드 추가 | 18 | 502.31 | 331.31 | 384.55 | 0.12% |
| 세대수 추가 | 18 | 502.31 | 328.86 | 382.35 | 0.69% |
| 학교 추가 | 19 | 502.31 | 331.21 | 384.42 | 0.16% |
| 역 접근성 추가 | 18 | 502.31 | 331.22 | 384.39 | 0.16% |
| 전체 추가 | 22 | 502.31 | 328.97 | **381.17** | **1.00%** |

MAE 단위: 만원/평. 추가 요소의 이득은 서로 더해지는 고정 프리미엄이 아니다. 같은 입력끼리 설명력이 겹칠 수 있다.

전체 추가 모델의 2025년 MAE 차이는 **−3.85만원/평**, 단지 단위로 300회 재표집한 95% 구간은 **−4.45~−3.32**였다. 이 구간은 해당 자료 안에서의 오차 차이이며, 과거 정보 복원의 편향이나 미래 성능 불확실성까지 포함하지 않는다.

전년도 동일 평형 거래가 없는 9,234개 평형에서는 **735.04 → 715.93만원/평, 약 2.60% 개선**됐다. 이런 이력 부족 사례에서 보조 지표를 활용할 근거가 있다. 지역별 MAE도 전체 추가 구성에서 서울 721.28→712.09, 경기 181.26→180.86, 인천 129.74→129.07로 낮아졌다.

## 왜 운영 v4는 유지하나

비교 전에 정한 선택 규칙은 **2023~2024년의 가중 MAE가 최고 구성과 0.5% 이내라면 입력이 가장 적은 구성을 선택**하는 것이다. 2025년 값은 이 선택에 넣지 않는다.

선택 기간 MAE는 v4 410.27, 세대수 추가 409.13, 전체 추가 409.19로, v4도 최고와 0.5% 이내다. 따라서 단순성을 선호한다는 요청에 따라 운영 구성은 v4로 유지한다. 2025년에 전체 추가 모델이 개선된 것은 유의미한 연구 결과지만, 그 시험 결과를 보고 선택 규칙을 바꾸거나 즉시 운영 모델을 교체하지 않는다. 별도 후보와 2026년 전체 33,242개 평형의 연구용 결과를 저장했다.

또한 이 연도들은 이전 v4 개발에서도 이미 살펴본 자료다. 완전히 새로운 미래 시험 기간으로 간주할 수 없다. 2026년이 마감된 뒤 동일 규칙으로 확인하는 것이 다음 검증이다.

## 과거 시점은 어떻게 처리했나

- **브랜드·연식·면적:** 거래 자료의 단지명과 준공연도·면적에서 추출한다. 현재 정정된 거래 이름이나 리브랜딩 이력의 한계는 남는다.
- **세대수·단지 좌표:** 기존 `apt_mst_info_202410.csv`를 사용한다. 주소·단지명·준공연도가 맞고 단지 ID가 유일할 때만 연결하며 재건축 표시 단지는 제외한다. 파일명에 202410이 있어도 당시 이 파일을 확보했다는 증거로 삼지 않는다. 과거에도 구조가 같았다는 가정 아래의 **회고적 복원 실험**이다.
- **학교:** 원본에 설립일자가 있어 대상 연도 이전에 설립된 학교로 제한한다. 하지만 현재 좌표·운영상태를 쓰므로 이전·폐교·과거 출입구는 완전히 재현하지 못한다.
- **역:** 서울시 현재 역사 마스터 784개 역·노선 항목을 수집했다. 이 중 개통 자료를 연결한 **130개 항목**만 운영 역 비교에 사용한다. 3·6·9호선과 신림선·진접선·별내선 일부 범위이며 수도권 전체 역망은 아니다. 확인된 역에서 2km보다 멀면 ‘역 없음’으로 단정하지 않고 자료 미확인으로 둔다.
- **계획·공사·개통:** 이벤트마다 발생일, 확인 가능한 발표일, 근거 URL을 저장하고 대상 시점에 알려진 최신 상태를 선택하는 구조를 구현했다. 별내선의 계획(2014), 공사(2015), 개통(2024) 사례를 연결했다. 이번 6개 모델 비교에는 운영 역 거리만 넣었으며 공사·계획 거리의 성능을 시험했다고 주장하지 않는다.

최종 2025년 시험 평형의 연결률은 세대수·학교 좌표 **64.48%**, 확인된 부분 역망 근접성 **20.45%**다. 특히 역 접근성의 작은 개선율을 ‘역세권이 중요하지 않다’는 결론으로 해석하면 안 된다. 현재 자료의 범위와 기존 가격 입력의 설명력이 겹치는 점을 함께 고려해야 한다.

## 면적별 세대수와 도보시간

공식 [국토부 공동주택 기본 정보 API](https://www.data.go.kr/data/15058453/openapi.do) 명세에서 `kaptMparea60/85/135/136` 항목을 확인했다. 이는 **60㎡ 이하 / 60~85㎡ / 85~135㎡ / 135㎡ 초과 구간의 세대수**이며 정확한 84.91㎡와 84.92㎡의 세대수를 구분하는 자료는 아니다. 이번 로컬 V5 API 요청은 시간 초과로 실패했으므로 실제 수치를 확보하거나 모델에 넣었다고 하지 않는다.

V5 수집기와 구간 세대수 검증 코드를 추가했다. 구간 합계가 단지 전체 세대수와 맞는 경우에만 해당 면적 구간의 세대수·비중을 사용할 수 있다. 불일치·결측을 거래수로 추정해서 채우지 않는다. 수집 시각도 저장해 이후 검증에서 과거 관측 가능 여부를 판단할 수 있다.

현재 보행 시간은 미확보다. 직선거리÷보행속도를 실제 진입 시간이라고 이름 붙이지 않았다. 다음 단계는 단지 출입구와 역 출입구, 횡단보도·보행망을 연결해 우회·대기시간을 포함한 경로 자료를 만드는 것이다. 학교도 가까운 학교와 실제 배정 학교를 구분해야 한다.

## 재현과 결과 파일

```bash
# 해시 검증된 원본으로 기존 빌드를 완료한 상태
python compare_preference_models.py

# 원본 단지/학교 CSV를 가지고 피처 스냅샷도 새로 만들기
python compare_preference_models.py --source-dir C:/code/data

# 현재 공식 역 좌표와 검증된 이벤트 메타데이터 갱신
python collect_metro_reference.py

# 승인된 기존 API 설정으로 면적 구간 세대수 수집 (성공 건별 체크포인트)
python collect_apt_preference_metadata.py --codes C:/code/data/kapt_code_list.csv --use-existing-config

python -m pytest -q tests
```

비교 수치는 [comparison JSON](preference_model_comparison.json)에, 재현용 추가 피처는 `metadata/preference_features_snapshot.json.gz`에 저장한다. 실행 결과 폴더 `.work/preference-experiment/`에는 후보 모델 `preferences-v5-research.joblib`, 전체 연구용 결과 `current_research_results.json.gz`, 비교 보고서가 생성된다. 모델 입력은 가격 목표를 보지 않고 만드는 피처이며, 출처와 해시를 스냅샷에 기록한다.
