# 국토부 CSV 수집 장애 진단 및 복구

공식 화면은 시도·계약기간(최대 1년)·주택유형·매매/전월세 조건으로 CSV를 제공한다. 수집기의 POST 필드와 건수 조회 → CSV 다운로드 순서는 관측한 공식 화면과 일치한다.

## 확인된 원인과 미확정 원인

- GitHub Actions 34298091259 / attempt 2는 기존 2006~2008 CSV를 재사용한 뒤 `Transport request failed (URLError)`로 끝났다. `transport retry` 로그가 없고, 초기화가 `_checked_download` 밖에 있으므로 초기 페이지 또는 시도 목록 요청 실패다. 앞서 세 차례 실패라고 안내한 내용은 정정한다.
- 이전 attempt 1의 2009 응답은 CSV가 아닌 형식이었다. 당시 MIME·응답 지문·기저 연결 오류를 충분히 보존하지 않아 서버 오류인지 세션 문제인지 확정할 수 없다.
- 같은 수집기 요청 형식과 동일한 경기 2009년 전체 조건으로 140,861행 다운로드 및 공식 조회 건수 일치 검증에 성공했다. 따라서 해당 연간 범위를 제공하지 않는다거나 연간 요청이 항상 너무 크다는 설명은 맞지 않는다.
- 성공 검증은 현재 작업 실행 환경에서 이루어졌다. 이것이 과거 GitHub Actions의 DNS/TLS/접속 장애 원인을 확정하거나 그 환경의 복구를 입증하지는 않는다. 재시도가 실제 성공 원인이었다고 주장하지 않는다.

## 수정 사항

- 초기화 요청에도 기존과 동일한 0~2회 제한 재시도를 적용한다. 같은 익명 클라이언트와 쿠키 저장소를 유지한다.
- 초기화 실패 이력을 본 작업 manifest에 기록한다. 전체 실패 단계와 마지막 요청의 허용된 엔드포인트를 남긴다.
- URLError 내부 예외 유형, errno, DNS/TLS/인증서/시간 초과/원격 종료 구분, 소요 시간을 남긴다. 인증서 검증 실패와 HTTP 오류는 자동 재시도하지 않는다.
- 응답 상태·MIME·크기·SHA-256·HTML/JSON 유사 형식을 기록한다. 세션 값, 쿠키, 임의 오류 본문, 민감한 URL은 기록하지 않는다.
- 원래 성공 파일 재사용 및 파일별 건수·금액·지역·기간 검증을 유지한다. 자동 월 분할은 추가하지 않았다. 초기 접속 실패는 기간을 줄여 해결할 수 없으며, 제한 응답을 분할 요청으로 회피해서도 안 된다.
