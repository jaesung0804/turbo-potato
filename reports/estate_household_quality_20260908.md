# 세대수 대비 거래량: 분모 범위 검증

검사일: 2026-09-08. 대상: 현재 잠재력 후보 3,699개 평형. 기존 시설 스냅샷은 2026-06-17에 보관한 자료이며, 세대수의 실제 관측일은 기록되어 있지 않다.

**현재 자료로 세대수 대비 거래량을 공개하거나 모형에 가중하지 않는다.** 단지명·준공연도 연결률은 높지만, 가져온 세대수가 단지 전체인지 일부 건물인지 확인할 수 없다. 실제 원천 거래의 층과 기존 세대수가 충돌하는 사례도 확인했다.

## 연결 범위

현재 실거래의 `구 코드 + 동·지번·단지명 + 전용면적`으로 후보를 일치시키고, 같은 동에서 이름이 같은 다른 지번은 제외했다. 단지 내 모든 평형의 세대수 값과 준공연도도 서로 같아야 연결로 인정했다.

| 검사 결과 | 평형 수 |
|---|---:|
| 전체 후보 | 3,699 |
| 단지명·준공연도가 보수적으로 연결됨 | 3,565 (96.38%) |
| 연결된 서로 다른 단지 식별단위 | 1,916개 |
| 기존 스냅샷에 이름 없음 | 75 |
| 세대수 없음 또는 유효하지 않음 | 53 |
| 같은 이름의 복수 지번으로 모호함 | 6 |
| K-apt·건축물대장 ID와 전체 범위를 검증한 세대수 | **0** |

96.38%는 **문자열·준공연도의 연결률**이다. 검증된 단지 전체 세대수 확보율로 해석하지 않는다.

## 확인된 범위 문제

| 거래 식별단위 | 기존 세대수 | 같은 지번·이름의 전체 이력에서 거래된 서로 다른 양수 층 | 판단 |
|---|---:|---:|---|
| 강동구 천호동 305 중앙하이츠 | 7 | 16개 층: 1~16층 | 단지 전체 세대수로 사용 불가 |
| 마포구 대흥동 806 마포그랑자이 | 66 | 23개 층 | 전체 단지인지 일부 건물인지 미검증 |
| 성북구 정릉동 239 정릉풍림아이원 | 332 | 20개 층 | 전체 단지인지 일부 건물인지 미검증 |

중앙하이츠는 취소·직거래를 제외한 아파트 실거래 36건에 16개 층이 관측된다. 기존 7세대와 이 층 이력은 그대로는 단지 전체 범위로 양립하기 어렵다. 이 검사는 올바른 총세대수를 새로 알아낸 것이 아니라 **기존 7을 분모로 쓰면 안 된다는 근거**다. 다른 두 단지도 대체할 정확한 세대수를 확인하지 못했으므로 숫자를 임의로 고치지 않는다.

원래 `load_complex_info`는 자료의 주소 중 구·동과 정규화한 단지명으로 사전을 만들고, 같은 키의 나중 행이 앞선 행을 덮어쓴다. 지번·개별 건물 ID·단지 전체와 개별 동의 구분은 그 과정에서 보존하지 않는다. 기존 `amenities_snapshot.json.gz`에도 지역·이름·준공연도만 남아 있다. 따라서 지금 문자열과 준공연도가 잘 맞더라도 원래의 여러 건물 중 어떤 범위를 가져왔는지는 복구할 수 없다. 이는 코드에서 확인한 구조적 문제이며, 원본 파일이 없어 개별 사례마다 어느 원천 행이 덮어써졌는지까지 증명한 것은 아니다.

공식 원장으로 의심 사례의 총세대수를 확인하는 공개 검색도 시도했지만 검증 가능한 공식 결과를 확보하지 못했다. 검색에 나타난 비공식 홍보 수치는 교정값으로 사용하지 않았다.

## 거래량 분자와 현재 화면 처리

거래량은 현재 자료로 계산할 수 있다. 2026-08-01을 마지막 날로 하여 **2026-02-03~2026-08-01, 양끝 포함 180일**의 모든 전용면적·모든 층 거래를 집계했다. 잠재력 후보의 특정 평형·3~20층 거래수만 가져와 단지 전체 세대수로 나누지 않는다.

다만 현재의 `구·동·지번·단지명` 묶음이 K-apt에서 관리하는 복수 지번·여러 단지명 표기의 전체 단지와 같다고 확인된 것도 아니다. 따라서 당장 공개한다면 **해당 거래 식별단위의 180일 거래 건수**로만 표시한다. 세대수로 나눈 회전율은 전체 범위를 확인한 뒤에 계산한다.

기존 세대수 표시를 모두 지우거나 값을 임의 보정하지 않고, `household_scope=unverified_legacy`, `households_verified=false`, `household_use_for_model=false`를 붙이는 방식을 권한다. 화면 문구는 **“기존 세대수 자료 · 단지 전체 범위 미검증”**으로 구분한다. 2026-06-17은 실제 세대수 조사일이 아니라 자료 보관일이다. 이 자료를 이용한 세대수 필터도 같은 상태를 드러내야 한다.

## 확보할 키와 검증 조건

1. **단지 ID:** K-apt 단지 코드 또는 검증된 건축물대장 단지 ID를 주키로 저장한다.
2. **지번·건물 범위:** 해당 단지의 전체 PNU 집합과 개별 건물관리번호 집합을 연결한다. 별칭이나 여러 지번을 갖는 단지는 이 집합으로 거래를 묶는다.
3. **세대수 분모:** 같은 기준일의 단지 전체 세대수를 사용한다. 개별 동별 자료라면 서로 다른 건물관리번호의 동만 합산하고, 반복 공개된 원본이나 같은 건물의 수정본을 중복 합산하지 않는다.
4. **거래 분자:** 같은 단지 범위의 모든 면적·층 거래를 집계한다. 거래 건수/세대수는 재매매도 포함하는 거래 회전율이며, 거래된 고유 세대의 비중과 구분한다.
5. **시점과 출처:** 원본 URL·레코드 ID·적용 기준일·최초 관측 시각·수집 시각·내용 해시·매칭 근거를 남긴다. 관측일 없는 현재 세대수를 과거 학습에 소급 입력하지 않는다.

추가 원장을 확보하면 먼저 현재 진단 지표로 표시하고, 이후 과거에 이용 가능한 자료로만 구성한 별도 비교 실험을 통과한 경우에 모형 입력으로 승격한다. 자세한 집계 수치와 키 설계는 `estate_household_quality_20260908.json`에 보관한다.
