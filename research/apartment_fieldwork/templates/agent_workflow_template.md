# 아파트 조사팀 운영 양식

버전: 1.0 · 공개 재사용 양식 · 개인 조건 기본값 없음

한 번의 조사 세션을 목표·오더·증거·검토·부분 저장으로 관리한다. 팀 직급은 책임의 구분이며 결제, 배포, 모델 학습 또는 자동 실행 권한을 추가하지 않는다. 이 문서는 정기 예약이나 상시 실행을 설정하지 않는다.

## 1. 역할과 책임

| 역할 | 책임 | 다음 담당자에게 넘길 산출물 |
|---|---|---|
| 총괄 대표 | 조사 목표와 우선순위 확정, 오더 배정, 결론 채택 여부 판단 | 채택·조건부 채택·보완·보류와 그 근거 |
| 동부권 조사팀장 | 담당 지역 단지 식별, 기본정보·생활요소·현장 근거 조사 | 정확한 면적·동·라인·층 범위를 가진 단지 노트 |
| 서남권·교통 조사팀장 | 담당 지역 단지와 같은 조건의 경로 비교 | 출발·도착 지점, 요일·시각, 환승·보행 범위가 있는 기록 |
| 미래 연구소장 | 현재 가격 신호와 조건부 미래 시나리오 해석 | 가설·반대 설명·민감도·추가 검증 과제 |
| 모델 검증 수석 | 기존 모델의 입력·목표·평가·출력 및 단지 식별 대조 | 읽기 검증 결과, 재현 경로, 오류·불확실성 목록 |
| 정책 수석 | 거시·대출·규제·공급의 공식 원문과 적용 범위 확인 | 발표·시행·관측기간·공표본을 구분한 정책 노트 |
| 기록관리실장 | 공개 자료 허용 목록 확인, 작은 커밋 저장, 스키마·해시·변경 범위 검증 | 저장 위치·커밋·체크포인트·누락 또는 차단 사유 |

역할은 필요에 따라 합치거나 담당 범위를 바꿀 수 있다. 자료 작성자와 결론 검토자를 식별하고, 같은 출처를 여러 팀이 인용했을 때 독립 근거 수를 늘리지 않는다.

## 2. 목표 분류와 비공개 설정

| 분류 | 설정할 값 | 기록 규칙 |
|---|---|---|
| 지역 | 지역 코드·행정구역·생활권·제외 지역 | 조사 지역과 개인의 선호를 구분. 개인 선택은 비공개 설정으로 보관 |
| 금액대 | 하한·상한·단위·가격 종류·취득 부대비용 포함 여부 | 개인 값은 공개 저장소에 넣지 않음. 호가·실거래·플랫폼 시세·모델 추정 구분 |
| 면적 | 전용면적 범위·정확 타입·공급면적 보조값 | 전용/공급, A/B 타입, 표시 소수점과 원자료 정밀도 구분 |
| 목적 | 실거주 비교·교통 비교·가격 학습·수익 사례 학습·정비사업 조사 등 | 과거 수익 사례 선정이 미래 수익 보장이 되지 않도록 목적을 명시 |
| 우선순위 | P0·P1·P2 | 아래의 판단 기준으로 오더마다 설정 |
| 증거 완성도 | 미착수·출처 확보·범위 확인·상충 검수·검토 완료 | 조사 진행 상태이며 출처 신뢰도 A~D나 모델 가격 신뢰도와 별개 |

개인 설정의 형식만 정의할 때는 값 없이 `region_include`, `region_exclude`, `price_min`, `price_max`, `currency`, `price_kind`, `exclusive_area_min_m2`, `exclusive_area_max_m2`, `purpose`처럼 매개변수 이름을 사용한다. 개인 후보 순위·예산·통근 조합·가족 일정·비공개 대시보드 주소를 공개 예제나 기본값에 넣지 않는다.

| 우선순위 | 기준 | 예시 질문 |
|---|---|---|
| P0 판단 차단 | 단지·면적 식별 오류, 가격 종류 혼입, 현재 적용 조건 미확인 등으로 비교를 진행할 수 없음 | 이 가격은 정확히 어느 타입의 거래인가? 현재 운행 역인가, 예정 역인가? |
| P1 핵심 비교 | 후보 간 생활 편의·가격·위험 차이를 크게 바꿀 항목 | 지하주차장에서 해당 동 승강기까지 이어지는가? 같은 시각 기준 경로의 대기·보행은 얼마인가? |
| P2 학습 | 즉시 판단을 막지는 않지만 설명력·사례 축적에 유용 | 과거 가격 상승에서 시장 공통 요인과 단지 요인을 어떻게 구분할 것인가? |

## 3. 오더의 필수 7항목

```yaml
order_id: null
owner: null
goal:
  question: null
  scope: null
  priority: null
  evidence_completion_target: null
basis:
  existing_evidence: []
  unresolved_issue: null
deadline:
  due_at: null
  timezone: null
completion_criteria: []
blocked_fallback:
  stop_condition: null
  alternative_public_source: null
  report_to: null
```

완료 기준에는 단순한 페이지 방문 수보다 판단에 필요한 결과를 적는다. 예를 들어 ‘대표점에서 역 출입구까지의 경로 URL·설정 요일/시각·거리·표시시간·횡단과 계단·관찰 한계를 저장하고, 실제 세대 현관 통근과 구분한다’처럼 검토 가능한 상태를 정한다.

접근 실패·상충·시간 부족이 생기면 확보한 부분을 먼저 저장하고, 실패한 원문·이유·대체 출처·남은 질문을 보고한다. 유료 전환, 새 API 결제, 접근제한 우회로 완료 기준을 채우지 않는다.

## 4. 보고서의 필수 7항목

| 항목 | 작성할 내용 |
|---|---|
| 1. 결론 | 질문에 대한 현재 답과 적용 범위. 확정할 수 없으면 그 상태를 명시 |
| 2. 사실·출처 | 원문 URL, 공개·관측·수집시점, 정확 단지/면적/동/라인/층/향, 주장별 신뢰도 |
| 3. 후기·추론 | 실제 후기 내용과 작성자 해석, 연구자의 추론을 분리 |
| 4. 반대·상충 | 반대 사례, 수치 불일치, 대체 설명과 현재 처리 |
| 5. 미확인 | 남은 질문과 확인 방법. 모름은 `null`, 부재 확인만 `false` 또는 `0` |
| 6. 순위 영향 | 순위를 바꿀 가능성과 조건. 개인 설정이 들어간 순위·점수는 비공개 보고 |
| 7. 제안 | 다음 행동, 필요 자료, 담당자, 보완 오더의 완료 기준 |

조회 시점에 없는 미래 가격이나 수익률을 만들어 채우지 않는다. 조건부 시나리오는 가정·전달 경로·반대 설명을 함께 제시한다.

## 5. 총괄 검토 상태

| 상태 | 의미 | 다음 처리 |
|---|---|---|
| 채택 | 오더의 완료 기준과 증거 범위 충족 | 해당 범위로 보고서에 반영 |
| 조건부 채택 | 특정 범위·가정에서는 쓸 수 있으나 확대 적용 불가 | 적용 조건을 결론 옆에 표시 |
| 보완 | 중요한 누락이나 상충을 추가 확인할 수 있음 | 질문·담당·기한이 있는 후속 오더 작성 |
| 보류 | 식별·원문·적용 조건이 불충분해 결론에 쓰기 어려움 | 자료는 보존하고 판단·순위 입력은 보류 |

총괄의 채택은 모델 학습 승인이 아니다. 초기 조사 기록의 `model_eligible`은 `false`로 두고, 모델 입력으로의 승인은 별도 검토한다.

## 6. 부분 저장과 종료 인계

1. 작성자는 허용된 공개 노트에 확인된 작은 묶음을 저장하고 기록관리 담당자에게 파일명·변경점·상충·개인정보 포함 여부를 알린다.
2. 기록관리 담당자는 공개 파일 허용 목록과 실제 내용을 확인하고, 전용 조사 브랜치에 작은 커밋으로 저장한다. 개인 자료와 원본 전체 추출물은 자동으로 함께 올리지 않는다.
3. 각 체크포인트에는 시점·상태·파일 해시·노트/단지/구조화 주장 수를 남긴다. 참조 URL 수를 검증 완료한 독립 출처 수로 표현하지 않는다.
4. 종료 시 원격 커밋·변경 경로·누락 여부를 확인한다. 연구 중단 시점을 넘겨 예약 실행하거나 유료 서비스를 생성하지 않는다.

기존 모델·배포·사용자 변경을 보존한다. 현재 세션에서 승인되지 않은 모델 학습·배포·유료 API·서버·유료 크롤링·새 Actions 실행은 시작하지 않는다. 저장소의 기존 자동 실행 조건을 먼저 확인하고, 조사 브랜치 또는 PR 작성이 실행을 유발한다면 요청 범위와 비용 조건에 맞는 저장 경로를 사용한다. 이 운영 규칙은 계정 전체의 청구 설정을 잠갔다고 보증하는 문구가 아니다.

## 7. 증거 규칙 연결

- 단지 기본정보는 플랫폼 원문으로 빠르게 확인하고, 식별 오류·상충·정책 적용 문제는 공식 문서로 보완한다.
- 공개일 `published_at`, 실제 관측일 `observed_at`, 수집일 `collected_at`을 분리한다. 알려지지 않은 실제 관측일은 `null`이다.
- 후기·광고는 그 성격과 주장별 신뢰도를 표시한다. 도면, 실제 실내사진, 외부사진, 거리뷰를 구분하고 촬영일을 확인한다.
- 지하주차장 존재, 승강기 직결, 단차 없는 연결, 외부에 노출되지 않는 연결을 별개 항목으로 기록한다.
- 지도 대표점·역 출입구 경로, 실제 현관·승강장 경로를 구분한다. 예정 교통망은 운행 중인 교통망과 분리한다.

자세한 관찰 항목은 [아파트 임장 조사 양식](apartment_inspection_template.md), 구조화 규칙은 [관찰 스키마](../schema/observation.schema.json)를 사용한다.
