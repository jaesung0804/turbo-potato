# 부동산 잠재력 시뮬레이션 규약 v1

목표는 **정해진 시점과 예산에서 이후 가격 상승과 비용 차감 후 선택의 질을 개선하는 피처·규칙을 찾는 것**이다. 현재 가격 추정은 기준가와 불확실성의 입력이다. 실제 매수 후보의 온라인 임장은 피처 가설과 근거를 공급한다. 시뮬레이션 성과가 임장 단지의 투자성을 보증하지 않는다.

이번 버전은 작은 실행 엔진과 합성자료 검증까지 준비했다. **실제 2023·2024년 컷오프 실험, 실제 수익률, 모델 재학습은 아직 실행하지 않았다.** 현재 backend에는 무료 설정·사용량을 독립적으로 검증할 계측이 없어 실자료 실행이 차단된다.

## 독립 시뮬레이션팀

| 담당 | 역할 | 완료 기준 |
|---|---|---|
| 정우 | SIMULATION 팀장 | 시점·예산·기간·대조전략을 사전 고정하고 작은 회차를 완주 |
| 민재 | 독립 검수 | 미래정보·체결·자금·분모·출구 누락 및 표본편향 검수 |
| 서진 | 모델 연결 | 임장 가설을 공통 피처 정의로 바꾸고 별도 검증에서 추가 가치 확인 |

임장팀과 별도의 실험 원장과 회의실을 둔다. 대표 결정사항과 팀 보고는 구분한다. 개인의 직장·가족 주소·통근 선호·관심 단지 여부는 학습 피처나 평가 표본의 선정 근거로 넣지 않는다. 개인 조건을 적용하는 매수 후보 화면은 모델 평가와 분리한다.

## 처음 실행할 비교 행렬

| 정보 마감 | 평가 구간 | 예산 축 | 정책 축 |
|---|---|---|---|
| 2023-12-31 KST 마감 | 2024년, 이후 24개월 별도 | 총 현금 6·8·10·12억, 예비현금 고정 | 한 채 매수 후 보유, 사전 정한 시점에 갈아타기 |
| 2024-12-31 KST 마감 | 2025년, 이후 24개월 별도 | 동일 | 동일 |

이는 시작 설계다. 실행 전 거래 가능 모집단·지역·단지×전용면적·최소 관측수·매수 지연·매도 시도 창·비용 시나리오·개발/검증 구간·가설 버전·입출력 목적지까지 기록한다. 24개월 실현 라벨이 아직 완료되지 않은 구간은 검증 완료로 처리하지 않는다. 표준 기본 실험은 대출 없는 1주택이며 실제 개인 예산을 뜻하지 않는다.

## 정보 누수와 당시 정보의 증거

1. 계약일, 최초 신고·공개일, 실제 관측일, 정정·취소가 관측된 시각을 별도로 보존한다. 계약일만 2024년이라고 2024년에 알려진 거래로 넣지 않는다.
2. `estate_vintages.rows_as_observed`의 당시 원장을 우선 사용한다. 최초 아카이브보다 앞선 기간을 현재 거래 DB로 복원한 경우 **신고지연 가정에 따른 재구성 실험**으로 표시한다. 엄밀한 당시 정보 검증으로 승격하지 않는다. 오늘 삭제된 취소거래, 정정된 가격, 현재까지 살아남은 단지 목록을 과거 표본에 소급하지 않는다.
3. 각 피처의 공개 가능 시각과 학습 라벨의 확정·공개 시각은 의사결정 마감 이하여야 한다. 지하철 개통·계획 승인·정비사업·입주 예정·일자리 통계·전세 자료는 당시 공개된 버전을 쓰며, 나중에 확인한 결과값을 계획 피처에 섞지 않는다.
4. 과거 컷오프별로 결측 처리·스케일링·모형·피처 선택을 다시 적합한다. 겹치는 12·24개월 수익 라벨은 학습/검증 경계에서 제거하고 간격을 둔다. 2024년에 미리 2025년까지 확정된 수익률을 학습 라벨로 쓰지 않는다.
5. 오늘 설계한 규칙으로 과거를 재생하면 시간순 실행을 지켜도 **회고 실험**이다. 이미 본 연도의 결과에 맞춰 바꾼 규칙은 동일 연도에서 독립 검증됐다고 표현하지 않는다. 실험횟수와 실패한 규칙을 보존하고, 별도의 미사용 구간 또는 앞으로 축적되는 관측으로 채택한다.
6. 입력에 요약된 `max_feature_available_at`·`max_training_label_available_at`는 실행 시점 필터다. 원래 피처 산출 코드의 무누수를 이 선언만으로 증명할 수 없다. 민재는 소스 원장·피처 변환·모델 학습 범위를 별도로 검수한다.

## 예산, 거래와 비용

- 매수가격 상한과 총 현금 제약은 다르다. 총 현금에는 취득 비용, 매수 중개비, 고정 비용, 이사비와 예비현금까지 포함한다. 호가가 올라 실제 실행 시 예산을 넘으면 미체결로 남긴다.
- 동일 예산·현금 잔액·평가 기간·출구 시점으로 보유와 갈아타기를 비교한다. 매도 계약금이나 잔금을 받기 전에 매수 자금을 만드는 처리는 금지한다. v1은 매도 잔금 완료 뒤 새 매수 계약과 잔금을 순차 처리한다.
- 실제 매물 증거와 거래가격 대리자료를 구분한다. 단지·면적 평균 또는 타인의 실거래는 그 집을 그날 살 수 있었다는 증거가 아니다. `transaction_proxy`는 비용·체결 기간을 둔 반사실 시나리오이며 실제 체결로 보고하지 않는다.
- 매수·매도 지연, 호가 관측 유효기간, 최소 보유기간, 미체결 만료를 미리 정한다. 매도 자료가 없으면 보유 상태를 유지한다. 말일 시세를 임의의 체결 가격으로 바꾸지 않는다. 말일 미청산·잔금 대기 계정은 실현 수익률이 `null`이다.
- 취득세·중개보수·양도세·보유세·이사/수리비·대출이자와 중도상환·임시거주 비용은 실제 날짜와 보유상태에 따라 달라진다. **주식 프로젝트의 편도 25bp를 옮기지 않는다.** v1 `Costs`는 명시한 비율·고정비의 민감도 계산이고 한국 세법 계산기가 아니다. 예시 비율은 전부 합성 테스트용이다.
- 실제 비용 시나리오를 채우기 전 해당 시점의 공식 규정과 적용 조건을 확인한다. 1주택/일시적 2주택/다주택, 보유·거주기간, 가격·면적·지역별 조건을 개별 시나리오로 분리한다. 대출·세제 특례·동시 잔금·임대보증금 인수는 v1에서 지원하지 않는다.
- 갈아타기의 거주 공백, 임시거주비, 실제 점유·인도일은 후속 비용·실행 모듈에 추가한다. v1의 거래비용 우위만으로 개인에게 갈아타기를 권하지 않는다.

## 사후 최선과 사전 전략의 구분

예산별로 **사전에 고른 자산의 비용 후 성과**를 평가한다. 같은 초기 모집단과 예산에서 사후에 가장 많이 오른 자산은 `ex_post_oracle`이라는 별도 참고 상한으로만 기록한다. 미래 승자를 모델 입력·모집단·임계값 조정에 쓰지 않는다. 실현 매도가 없는 후보를 사후 최적 계산에서 조용히 제외하지 말고 미청산 비율과 모집단 감소를 함께 표시한다.

첫 대조전략은 현금 유지(이자 0 가정), 동일 예산 내 최저가 단지 매수 후 보유, 잠재력 점수 1위 매수 후 보유, 사전 주기의 잠재력 갈아타기다. 후속으로 당시 적격 모집단에서 시드를 고정한 무작위 1채와 같은 지역·가격대의 단지 비교를 추가한다. 주택은 분할매수가 어려우므로 주식식 균등 비중 포트폴리오를 개인의 가능한 선택처럼 쓰지 않는다.

평가는 매수가 대비 상승률 외에 초기 총자금 대비 비용 차감 수익, 현금·보유자산·비용, 미체결·미청산·가격누락 비율, 예산별 순위/후회값, 지역·가격대·유동성별 성과, 비용·체결지연 민감도를 함께 본다. 월별 시세가 없는 단지는 일별 최대낙폭을 계산해 정확한 위험 측정인 것처럼 게시하지 않는다. 후보 묶음의 불확실성은 단지와 시점의 의존성을 고려한다.

## 저장과 재개 게이트

원거래·전세·피처 패널·모델·원장은 DB의 메타데이터와 인증 OCI 파일 저장소에 압축 보관한다. Git에는 코드, 작은 규약·검증 요약·배포에 필요한 최종 주요 자료만 둔다. 스냅샷이 없거나 복원 SHA가 다르거나 용량·무료 설정을 확인할 수 없으면 의존 작업을 멈춘다. Git 업로드·전체 재수집·빈 DB 시작으로 대체하지 않는다.

`estate_research_storage.run_preflight`가 실제 `/ready`, 스냅샷 head, 최초 복원 영수증, 압축 파일 SHA/복원 CRC, 체크포인트 버전, 무료 용량과 예상 증분을 검증해야 한다. 손으로 쓴 `ready=true` JSON은 실행 권한이 아니다. 현재 API에 없는 무료/용량 계측을 성공했다고 꾸미지 않는다. 20GB 도달 시 자동 삭제를 제공사 보장으로 전제하지 않으며 보존에 필요한 여유를 먼저 확보한다.

v1 입력은 **복원된 비압축 5MB·10,000행 이하**의 피처/호가 패널 한 개다. 원본 전체를 메모리나 Git으로 가져오지 않는다. 체크포인트는 입력·정책·비용·엔진 SHA, 원본 snapshot ID, 다음 날짜, 현금·보유·미결 주문·잔금, 누적비용과 원장을 보존한다. 압축본 업로드 후 다운로드 SHA를 확인하고 작은 체크포인트 레코드를 CAS로 갱신한다. 409는 중단이며 새 버전만 얻어서 오래된 계산을 강제로 올리지 않는다.

이번 버전의 기본 주기는 30일이고 회차 종료 때도 저장한다. 프로세스가 중단되면 동일 입력·정책·엔진의 마지막 검증 체크포인트에서 재개한다. 입력·코드·규칙이 달라지면 새 실험 ID를 만든다. 압축 체크포인트 또는 새 증분이 한도를 넘으면 추가 실행을 막는다. 모델 원본과 대규모 원장까지 처리하는 스트리밍 엔진은 아직 구현하지 않았다.

## 간단한 회차 보고와 인수인계

회차 보고는 목적 관련 발견, 모델에 반영할/기각할 피처, 실제 매물의 핵심 미확인 해소, 다음 검증과 차단 사유만 짧게 쓴다. 코드 테스트 성공을 잠재력 성능 개선으로 보고하지 않는다.

인수인계에는 실험 ID·스냅샷/입력/코드 해시·마지막 저장 버전·다음 날짜·완료/미완료 범위·막힌 이유·다음 실행명령을 남긴다. 정우의 실행, 민재의 검수, 서진의 모델 반영, 대표 결정 상태를 분리한다.
