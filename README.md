# 수도권 아파트 실거래 비교

서울·경기·인천의 아파트 실거래를 단지·지번·정확한 전용면적별로 비교하는 정적 대시보드입니다. GitHub Actions에서 수집·학습·추론을 수행하고 GitHub Pages에는 압축된 결과와 HTML/JS만 공개합니다.

## 현재 운영하는 두 가지 분석

| 화면 | 답하는 질문 | 계산 기준 |
| --- | --- | --- |
| 실거래 저평가 비교 | 이 가격은 현재 기준가보다 얼마나 낮은가? | 월별 F50와 표시 가격으로 점수·할인율을 동일하게 계산 |
| 상세의 계약 당시 평가 | 그 거래는 계약 당시 기준가보다 얼마나 낮았나? | 계약월 시작 31일 이전의 이력과 실제 거래 층으로 계약별 재평가 |
| 별도 잠재력 페이지 | 향후 주변 다른 단지보다 강하게 재평가될 후보인가? | 성숙한 과거 상대 변화로 학습한 18~24개월 후보 순위 |

목록·지도·필터·입력 계산기·CSV는 `valuation_comparison`을 공통으로 사용합니다. 기준가 재입력은 정확히 50점이며 거래 표본 수는 가격 차이와 분리해 표시합니다. 현재 비교가격은 자료 마감까지 최근90일 실거래 중앙가이며, 계약 당시 점수와 구분합니다. 기본 목록은 기준가 입력 이력과 비교 거래가 각각3건 이상인 평형입니다. 전체 조회에서는 희소 자료와 미산출 평형도 보존합니다. 이전 연간 `house_match_score`는 감사용으로만 남깁니다.

현재 월별 가격 모형은 `estate-nowcast-v1`, 점수 표현은 `estate-discount-v1`입니다. 2026년 3월 이후 계약별 재평가는 `estate_valuation.py`에서 원천·모형·명세 해시를 확인해 생성합니다. 1~2월과 학습 연도의 계약에 검증되지 않은 점수를 채우지 않습니다. 상세 계약 자료와 잠재력 자료는 별도 gzip으로 나누며 필요할 때만 읽습니다.

잠재력은 `price_activity_relative_growth_24m_policy_v2`의 고정 연구 후보입니다. 현재 적정가와 합산하지 않고, 실제 입력·주요 모형 기여·31/61일 시차 가정에 따른 순위 변화를 함께 표시합니다. 5년 목표와 추가 데이터 설계는 [잠재력 설계 기록](reports/estate_potential_design_v2.md), 현재 가격의 전체 일관성 검사는 [가격 검증 기록](reports/estate_valuation_consistency_20260908.md), 실제 공개 시차 관측은 [시차 감사](reports/estate_reporting_lag.md)에 있습니다.

2006~2015년 원본 740,326행을 추가 확보해 5년 모형도 17개 판단 시점에서 순차 검증했습니다. 사전 기준을 통과하지 못해 5년 순위를 추가하지 않았으며, 완료된 결과와 좁은 결과 관측 기간의 한계를 [5년 실험 결과](reports/estate_potential_five_year_results.md)에 남겼습니다. 추가 원본은 `estate-history-extended-state`의 실행별 스냅샷으로 보존합니다. 기존 세대수는 단지 전체와 개별 동의 범위가 검증되지 않아 [세대수 품질 검사](reports/estate_household_quality_20260908.md)에 따라 표시용으로만 유지하며 거래 회전율·모형 가중치에 사용하지 않습니다.

## 2026-09-08 후속 감사와 운영 보완

[요청별 완료 범위](reports/estate_request_completion_20260908.md)를 실제 코드·원자료로 대조했습니다. [최근 가격 비교](reports/estate_recent_comparison_20260908.md)는 20,386개 평형에서 동일 가격·점수 일치, 기본 근거 조건5,680개를 확인했습니다. 3건 조건은 탐색 필터이며 정확도 보장이나 새 가격모형 재학습을 뜻하지 않습니다.

[24·36·48·60개월 경로 실험](reports/estate_potential_path.md)은 결과 가격창을12개월로 넓혀17개 시점을 시험했습니다. 측정 가능성은 개선됐지만 고정한 비교에서 단순 소외 규칙보다 좋지 않아 미채택했습니다. 기존24개월 운영후보에 새 경로점수를 합산하지 않습니다.

`refresh_estate_potential.py`와 월별 workflow는 서울·광명의 기존24개월 v2만 재검증하고 새 월의 학습표·모형·예측·검증 지문을 `estate-potential-state`에 보존합니다. 같은 달 예측을 덮어쓰지 않으며, 매월10일05:00UTC에 실행해 성공한 후보를 Pages로 배포합니다. 원본 불일치·관측 부족·실행 실패에서는 이전 공개본을 유지합니다. 최초9월은 원래 예측을 그대로 가져왔으며 당시 exporter가 저장하지 않았던 fitted model을 복원했다고 주장하지 않습니다.

[서울 공식 세대수 원장](reports/estate_household_sources_next.md)2,887개를 확보했습니다. 공적인 주소 대조까지 완료한 마포그랑자이의 현재 표시만66→1,248세대로 정정합니다. 단지 전체 거래 범위·과거 분모 유효시점이 미검증이므로 회전율 학습에는 사용하지 않습니다.

## 전체 결과 조회

기존의 지역별 70개 저장 제한, 목록·AI·지역 순위 표시 상한을 없앴습니다. 50개씩 페이지를 그리지만 원본 집계에서 모든 단지·평형을 보존합니다. 전체 검색과 CSV 다운로드는 현재 페이지와 관계없이 필터에 맞는 전부를 사용합니다. 모델 점수가 없어도 전체 단지 목록에서 사라지지 않습니다.

정확한 구분 단위는 `시군구 + 읍면동 + 지번 + 단지명 + 전용면적(㎡)`입니다. 다른 지번의 동명 단지나 정수 평수는 합치지 않습니다. 원본 면적의 소수 자릿수를 보존합니다. 원본의 직거래·해제·유효하지 않은 거래는 가격 집계에서 제외하되, 수집 원본에는 보존합니다. 거래되지 않은 단지·평형까지 포함하는 매물 DB는 아닙니다.

공통 단지 색인, 작은 연도별 이력, 연도별 상세 파일을 gzip으로 나눠 읽습니다. `dashboard_manifest.json`에 원본 집계 거래수, 목록에 보존된 거래수, 평형수, 파일 SHA-256을 기록합니다. 건수나 해시가 맞지 않으면 이전 화면을 유지하거나 공개를 중단합니다.

## 이전 연간 기준모델 개발 기록

아래는 이전 `estate-reference-v4` 개발 기록입니다. 현재 공개 점수는 위의 월별 기준으로 대체했으며, 연간 v3·v4·v5 모형 파일과 검증 결과는 보존합니다. [17개 피처·학습 방식·점수 공식·중요도·보완 계획](reports/estate_model_explained.md)은 이전 연간 모형에 대한 설명입니다.

- 입력: 앞선 연도의 동일 평형 중앙 가격, 주변 중앙 가격, 가격 변화, 거래수와 지역·면적·당시 연식.
- 학습: 작은 LightGBM 모델과 전년 가격 기준의 혼합. 혼합 비중은 직전 연도에서 선택합니다.
- 검증: 완결된 연도의 확장식 시간 분할. 비중 선택과 구간 보정은 직전 연도의 서로 다른 단지 집합으로 분리합니다. 시험 연도의 결과를 보고 혼합 비중을 정하지 않습니다.
- 오차: MAE(만원/평), 중앙 절대 오차율, ±20% 이내 비율, 지역별 오차와 80% 목표 구간의 실제 포함률을 공개합니다.
- 검토점수: 기준가격보다 관측가격이 낮으면 50보다 높아지는 비교 순서입니다. 표본 수와 과거 오차로 조정하며 상승 확률이나 예상 수익률이 아닙니다. 거래가 적어도 숨기지 않고 표본 경고와 넓은 범위를 표시합니다.
- 월 고정: `models/estate-reference-v4/YYYY-MM.joblib`을 한 번 생성한 뒤 같은 달에는 덮어쓰지 않습니다. 기존 v3 파일도 보존합니다. 매일 같은 모델로 새 관측자료를 비교합니다. API 정정으로 자료 자체는 바뀔 수 있습니다.

시설 자료는 이전 저장본에서 일치하는 이름·준공연도만 보수적으로 이어받았습니다. 같은 이름의 다른 지번이 있으면 자동 연결하지 않습니다. 실제 관측일이 없어 과거 학습에는 사용하지 않으며 미확인은 빈 값으로 남깁니다. 표시용 스냅샷의 출처는 `metadata/amenities_snapshot.json.gz`에 기록돼 있습니다.

## v4 모델 비교와 적용

2026-09-06 UI·데이터 검증 개선과 함께 빌드·학습 CLI 기본값을 `estate-reference-v4`로 바꿨습니다. 기존 v3 파일을 덮어쓰지 않고 별도 버전·월 파일을 저장합니다. 동일 평형의 전년도 거래가 없을 때 최근 3년 이력을 찾고, 이력이 없으면 비슷한 면적의 동·구·시도 가격을 비교 기준으로 씁니다. LightGBM은 기준가격에서 벗어난 로그 가격 차이를 학습합니다. 거래 표본 수로 보정한 오차를 지역·전년도 이력 유무별로 나눠 가격 범위를 계산합니다.

2026-09-05까지 복원된 전체 자료의 2023~2025년 시험 평형 98,410개에서 가중 평균 MAE는 **437.75 → 400.96만원/평(8.40% 감소)**였습니다. 연도별 감소율은 **8.48%, 9.76%, 7.22%**입니다. 서울·경기·인천의 각 시험 연도에서도 MAE가 감소했습니다. v3를 같은 Windows 환경에서 다시 학습한 전체 MAE는 기존 공개 검증값과 일치했습니다.

가격 범위는 아직 주의해서 해석해야 합니다. v4의 연도별 포함률은 **77.40%, 93.14%, 81.16%**이며, 2023년 전년도 이력 보유 집단은 **67.35%**에 그쳤습니다. 2025년 전년도 이력이 없는 집단도 **75.66%**였습니다. 과거 가격 오차 개선이 미래 수익률이나 구간의 신뢰도를 보장하지 않습니다. 비교를 근거로 운영 모델을 자동 교체하지 않습니다.

[전체 비교 JSON](reports/estate_model_comparison.json) · [저장소 점검 및 검증 기록](reports/estate_model_audit_20260906.md). 사용법 페이지의 **후보 모델 비교**에서 동일한 결과와 집단별 오차를 볼 수 있습니다. 보고서는 해당 자료 스냅샷의 결과이며 일 배치마다 새로 수행한 실험은 아닙니다.

```bash
# 전체 집계가 만들어진 뒤 동일 자료로 두 모델 재비교
python compare_estate_models.py
# 기존 v3 월 모델과 별개로 v4 월 모델 생성/재사용
python train_house_match_model.py --model-version estate-reference-v4 --output .work/build/recommendations_v4.json
# 후보의 전체 결과를 별도 로컬 사이트로 생성
python build_public_site.py --model-version estate-reference-v4 --output .work/site-v4
python run_real_estate_dashboard.py --skip-build --site-dir .work/site-v4
```

Windows/Python 3.12 환경에서 LightGBM 4.7.0의 최소 학습·추론 예제가 접근 위반으로 실패해 Windows만 4.6.0을 사용합니다. Linux의 4.7.0 고정은 유지합니다. 비교 JSON에는 실행 환경과 입력 SHA-256을 기록합니다. 한국어 JSON·HTML은 UTF-8로, 텍스트 줄바꿈은 LF로 저장합니다.

## 수집과 상태 보존

`collect_estate_transactions.py`는 국토부 일반 아파트 매매 API의 모든 페이지를 읽습니다. 상세 API의 권한에 의존하지 않습니다. 2026년 9월 기준 83개 시군구와 2021년 이후 계약 월을 조회합니다. 부천·화성·인천 개편 지역의 과거 자료가 새 코드로 반환되는지 별도로 확인했습니다.

- 완결된 `계약 월 × 시군구` 파티션마다 해시·응답 건수·조회 시각을 저장합니다.
- 인증서를 검증하는 TLS 1.2 연결을 작업별로 재사용합니다. 요청마다 25초 제한과 재시도, 실패한 파티션만 다시 처리하는 체크포인트가 있습니다. 연속 10개 파티션이 모두 실패하면 연결 장애로 중단해 무한 대기를 피합니다.
- 취소 필드 `cdealDay/cdealType`과 기존 필드명을 모두 처리하며 호환되지 않는 이전 캐시는 재사용하지 않습니다. 전체 파티션 검증 후에만 CSV와 `estate-raw-state`를 교체합니다. 일부 실패로 기존 전체 원본을 덮지 않습니다.
- 일 갱신은 최근 3개월과 순환하는 과거 1개월만 다시 읽습니다. 월이 66개 남아 있으면 오래된 각 월은 대략 66일에 한 번 다시 검사합니다. 즉시 반영되는 과거 정정이라고 보장하지 않습니다.
- 원본은 변경된 월·시군구 압축 파일만 Git에 반영하는 `estate-raw-state`, 월별 모델은 `estate-model-state`에 분리 저장하며 파일 크기·SHA-256을 확인하고 원본 CSV를 다시 조립한 뒤 전체 해시를 확인합니다. 조회 시각만 달라진 과거 거래는 같은 Git 데이터 객체를 재사용합니다.

`MOLIT_API_KEY` 환경 변수/GitHub Secret을 우선 사용합니다. 이번 이전 작업과 기존 설정 호환을 위한 `--use-existing-config`는 저장소에 이미 제공된 인증 설정을 읽으며 별도 파일에 키를 복제하지 않습니다. 로그에는 인증 값을 출력하지 않습니다.

## 실행

Python 3.12를 사용합니다.

```bash
pip install -r requirements.txt
# estate-raw-state와 estate-model-state를 별도 디렉터리로 받아 복원
python raw_estate_state.py restore --state-dir .work/raw-state
python estate_model_state.py restore --state-dir .work/model-state
# 완전성 확인 → 전체 집계 → 해당 월 모델 생성/재사용 → 압축 사이트
python build_public_site.py
```
