## 대시보드 사용

지역·연식·평형·호선은 여러 개 선택할 수 있습니다. 같은 항목 안에서는 합집합, 다른 항목끼리는 교집합입니다. 예를 들어 서울·경기와 신축·준신축을 함께 고를 수 있습니다. 페이지를 넘겨도 다운로드에는 조건에 맞는 전체 결과가 들어갑니다.

현재 기준가는 P50 중앙값이며 P10·P90을 함께 표시합니다. 낮은 거래를 증여라고 판정하거나 가격 때문에 원본에서 제거하지 않습니다. 현재 가격 비교점수와 장기 상승 잠재력은 별도 분석입니다. 과거 계약 당시 평가에는 당시 적용 가능한 기존 모델을 유지합니다.

## 엑셀과 자동 채우기

**임장 비교표 Excel**은 `임장 비교`와 `기준 및 출처` 두 시트입니다. 첫 시트에 가격·주차·용적률·대지지분·초품아·역·이동 시간 등 실전 비교 항목을 모았습니다. 내부 키와 확인 상태 열은 없고, 임장·메모는 비워 둡니다.

**자동 채우기 받기**를 풀고 `fill.cmd`를 실행하면 공개 단지 정보를 조회해 별도 완성본을 만듭니다. Python 3.12 이상과 Windows Edge가 필요하며 API 키는 필요 없습니다. 선택적으로 `FillEstate.bas`를 가져와 Excel 버튼으로 실행할 수 있습니다. 원본과 직접 적은 임장·메모는 보존합니다.

직장·본가 모두 평일 오전 8시 출발 대중교통입니다. 목적지는 개인 브라우저 설정과 내려받은 엑셀에만 저장됩니다. 네이버 지도에서 확인된 목적지 경로가 있어야 자동 조회하며 이름만으로 다른 장소를 고르지 않습니다. 출처에 정확한 값이 없는 항목은 임의 계산하지 않습니다. 초품아는 현재 모델의 초등학교 500m 이내 지표로, 실제 배정·통학로와 구분합니다.

## 현재 채택 모델

2026년 10월 8일 로컬에서 비교한 `estate-quantile-capital-v1`입니다. 기존 L1 중앙값에 LightGBM 분위수 회귀로 학습·보정한 양쪽 경계를 결합했습니다. 2026년 7~8월 동일 거래 37,296건에서 중앙값 오차는 동일했고 목표 80% 범위 포함률은 **77.99%→80.14%**, 평균 분위수 손실은 **0.018134→0.018060**이었습니다.

여러 후보를 순차 검토한 재사용 자료 평가입니다. 미래 독립 검증이나 TFT·Chronos-2와의 직접 성능 대결로 해석하지 않습니다. 각 꼬리의 보정은 불완전하며 범위 폭은 약 7.5% 넓어졌습니다. [전체 결과와 한계](reports/estate_quantile_results_20261008.md), [수치 원장](reports/estate_quantile_results_20261008.json), [채택 명세](metadata/nowcast_quantiles_2026.json)를 함께 확인하세요.

## 저장소 구성

| 위치 | 내용 |
| --- | --- |
| `web/` | 공개 화면과 엑셀 내보내기 |
| `excel_helper/` | 로컬 자동 채우기 프로그램·Excel 실행 매크로 |
| `tests/` | 데이터 연결·모델·화면·개인정보 보존 검사 |
| `metadata/` | 작은 모델 명세·공개 기준 자료 |
| `reports/` | 날짜가 있는 실험 결과와 감사 기록 |
| `docs/` | 한글 운영·재현 지침과 과거 인계 |
| `.work/`, `models/` | Git에서 제외된 로컬 자료·후보·모델 캐시 |

사용하지 않는 과거 대용량 JSON 5개는 작업 트리에서 제거했습니다. 과거 기록과 모델 비교 기준은 Git 이력에 남습니다. 현재 원본과 체크포인트는 기존 DB/OCI 상태 관리 규칙을 따릅니다. 선택한 로컬 공개 모델·완성 사이트만 체크섬을 고정한 Release로 배포하며 원자료·개인 엑셀은 올리지 않습니다.

## 수집과 운영

국토부 공개 CSV 내려받기 경로를 지원합니다. 인증키 수집과 구분해 출처·수집일·계약일·정규화 버전·해시를 남깁니다. 오늘 실행했다는 이유로 실제 계약 마감일을 오늘로 바꾸지 않습니다. 현재 공개 자료의 날짜와 완전성은 화면의 자료 상태에서 확인합니다.

푸시와 페이지 조회는 전체 수집·학습을 실행하지 않습니다. 정기 수집과 월별 잠재력 연구는 기존 일정으로 유지하고, 수동 로컬 모델 교체는 별도 검증 후 배포합니다. 백엔드 복원·CAS·실패 복구 규칙은 [AGENTS.md](AGENTS.md)와 [배포 지침](GITHUB_PAGES_DEPLOY.md)을 따릅니다.

[이전 상세 개발 기록](docs/development-history-202609.md)은 당시 상태를 담은 기록이며 현재 사용법보다 우선하지 않습니다.
